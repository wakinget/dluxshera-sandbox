# SHERA ML Master Dataset V4 Specification

Status: design frozen for Task 2 implementation of deterministic state-plan
materialization and QA. This document does not authorize rendering.

## Scope

This task audited existing rendered-dataset infrastructure, characterized the
local historical sparse 100k context package, and defines the V4 master
rendered-state dataset. Non-goals remain: no production rendering, no S01/S05
training changes, no pair selection implementation, no composite catalog
implementation, no SLURM arrays, no historical relabeling.

V4 is a logical master collection composed of multiple rendered-state
geometries. The immediate scientific gap is full-dimensional generalization:
current S01/S05 models perform well on structured V3 pair-grid geometry, but
that does not prove corrections generalize to arbitrary joint perturbations.

## Current Infrastructure Audit

Raw V3 generation is implemented by
`work/experiments/generate_training_dataset_v3.py`.

The generator resolves a system and experiment prescription, builds a
`SheraBinder`, computes Fisher-diagonal scales at the nominal state, writes
plan artifacts, then optionally renders samples. The generated raw contract is:

- `manifest.json`: schema, generator, script version, system summary, noise
  config, nuisance config, sweep config, plan counts, render progress, git info.
- `prescription_input.json`: user prescription before resolution.
- `prescription_resolved.json`: resolved system and experiment config.
- `parameter_space.json`: ordered scalar science parameters and Fisher scales.
- `pair_plan.csv`: pair-grid plan rows.
- `sparse_mixture_plan.csv`: sparse random plan rows.
- `samples.jsonl`: one rendered sample row per completed image.
- `images/sample_*.fits` and `images/sample_*.json`: rendered image plus per
  sample metadata.

Raw science states are represented as sparse mappings in each row:
`theta_delta`, `theta_sigma`, `theta_nominal`, and `theta_applied` where
available. Pair-grid rows store controlled labels and grid coordinates; sparse
rows store active labels/masks/counts. Prepared datasets convert the sparse
mapping into ordered `physical_delta` and `fisher_scaled_delta` arrays.

Authoritative current ordering is produced by `_scalarize_parameter_space` from
`experiment.sweep_keys`, resolved `ParameterStore` values, and the packed
`ParamSpec`. The order is then frozen in `parameter_space.json` and, for
prepared data, in `vector_spaces.json` using `VectorSpaceSpec` and
`VectorComponentSpec`.

Fisher scales are computed by `_compute_fisher_sigmas` using the nominal binder
image, `make_binder_nll_fn`, `fim_theta`, and `build_index_map`. They are
materialized as `parameter_sigma` in `parameter_space.json` and as the
`fisher_diagonal_scale` transform in prepared `vector_spaces.json`.

Parameter sweep/range definitions come from `experiment.sweeps`, keyed by base
parameter with fallback to `experiment.sweeps.default`. The generator records
`min_sigma`, `max_sigma`, `min_abs_delta`, and `max_abs_delta`. It does not
currently write explicit physical lower/upper bounds as a separate stable
machine-readable contract; the intended symmetric physical range must be
inferred as nominal plus/minus max absolute delta.

The nominal science state comes from resolved `ParameterStore` defaults plus
`experiment.nominal_values`. It is stored per scalar component in
`parameter_space.json` and, for sparse rows, in `theta_nominal`. Units are weak:
the present sparse 100k `parameter_space.json` has `units: null` for all 20
components, including Zernike coefficients that are named in nm. V4 must
preserve units explicitly.

Nuisance states are generated by `_build_nuisance_draws`. The current
registration nuisance vector is:

1. `source.x_position_as`
2. `source.y_position_as`
3. `source.position_angle_deg`

Nuisance values are drawn in Fisher-sigma coordinates from the same
`experiment.sweeps` machinery, then converted to physical deltas. Nuisance IDs
are integer draw IDs. When `include_nominal=false` and `n_random=10`, IDs are
1 through 10. V3 stores nuisance values in
`registration_nuisance_values` and `registration_nuisance_sigma_values`.

Pair-grid rendering applies every grid point over each nuisance draw, so it has
a nuisance-replicate mechanism. Sparse-mixture rendering samples exactly one
nuisance draw per sparse science sample. There is no generic, reusable
science-plan x nuisance-bank materializer separated from the V3 generator; V4
should generalize this.

Images are rendered by `_render_sample`, which applies deltas to a
`ParameterStore`, builds a binder model, optionally applies noise, writes FITS,
and appends `samples.jsonl`. Sample IDs are generated as monotonically
increasing `sample_%06d`. Sparse-only runs start at `sample_000000`;
pair-grid-plus-sparse runs place sparse samples after pair-grid samples.

Prepared datasets are built by `src/dluxshera/datasets/shera.py` via
`prepare_shera_v3_dataset`. This streams raw FITS images into `.npy` shards
with `ArrayShardStore`, writes `index.jsonl`, copies source provenance hashes,
writes vector spaces, and validates readback precision. It is V3-specific but
uses reusable primitives:

- `VectorSpaceSpec` / `VectorComponentSpec`
- `DiagonalScaleTransform`
- `ArrayShardStore` / `ArrayShardReader`
- `assign_grouped_split`
- `compare_arrays`

ML catalogs are loaded by `src/dluxshera/ml/catalog.py`. A `SampleCatalog`
retains sample IDs, array indices, science group IDs, nuisance group IDs,
family/role IDs, ordered physical deltas, Fisher deltas, nuisance vectors, and
Fisher sigmas.

Split registries are built by `src/dluxshera/ml/splits.py`.
`generate_split_registry` independently partitions science groups and nuisance
groups by stable hashes. Science grouping currently uses
`group_ids.physical_delta_sha256`; nuisance grouping uses `nuisance_id`.

Pair datasets are generated by `src/dluxshera/ml/pairs.py`.
`PairSampler` supports:

- `same_nuisance_different_science`
- `same_science_different_nuisance`
- `different_science_different_nuisance`

Targets are `target_delta_z = z_B - z_A`, `target_delta_theta`, and
`nuisance_delta`. Frozen validation/test pair manifests are written by
`generate_frozen_pair_manifest` and `write_pair_manifest`.

Reusable for V4:

- ordered vector-space metadata classes;
- diagonal Fisher transform representation;
- sharded array storage/readback;
- source provenance hashing;
- split-registry concepts;
- sample catalog grouping by science and nuisance identity;
- pair-family sampler semantics.

Needs generalization for V4:

- state-plan generation should be family-generic, not V3 pair-grid-specific;
- nuisance-bank generation should be separated from science-state plans;
- full science x nuisance cross-product should be a first-class materializer;
- sample/state IDs should be stable semantic IDs, not only sequence numbers;
- units and physical lower/upper bounds need stable machine-readable fields;
- `parameter_space.json` should be replaced or augmented with explicit
  `VectorSpaceSpec` contracts at raw-plan time;
- renderer/source commit and content hashes should be mandatory in plan/render
  manifests;
- prepared/composite catalogs should select logical families without copying
  raw renders.

## V4 Metadata Contract

Every V4 state/render record must preserve ordered vector metadata explicitly.
Do not rely on JSON dictionary key order.

Common required fields:

- `dataset_version`
- `dataset_family`
- `split_role`
- `science_state_id`
- `sampling_method`
- `sampling_version`
- `sampling_seed`
- `sequence_index`
- ordered physical science vector
- ordered Fisher-scaled science vector
- normalized sampling coordinates where applicable
- `fisher_radius_l2`
- `active_parameter_count` where applicable
- `active_parameter_indices` or mask where applicable
- `nuisance_id`
- ordered nuisance vector
- `science_vector_space_id`
- `nuisance_vector_space_id`
- optical preset
- detector preset/configuration
- wavelength/bandwidth/exposure/render settings
- renderer/source commit
- render schema version
- output image identity/path
- content hashes where appropriate

`radial_capture` adds:

- `requested_fisher_radius`
- `actual_fisher_radius`
- `radial_bin`
- `direction_sequence_index`

Sparse families add:

- `active_parameter_count`
- `active_parameter_indices`
- `active_parameter_mask`

Family-specific fields are not required for unrelated families.

Stable IDs should be content-derived from dataset version, family, split,
ordered science vector-space ID, sequence index, and sampling seed. Render IDs
should additionally include nuisance bank ID and nuisance ID.

## V4 Nuisance Bank

V4 separates the science-state plan from the nuisance-state bank. The preferred
bank for Task 2 is the exact recovered 10-state legacy bank above, because
values and provenance are clean and compatible with the current 3-D nuisance
vector.

V4 rendering should use full cross-product replication:

```text
each science state x each nuisance state
```

This supports same-science/different-nuisance, different-science/same-nuisance,
science+nuisance mismatch, nuisance-invariance training, held-out nuisance
identity, and arbitrary A/B registration mismatch.

Canonical renders remain noiseless. Stochastic photon/read noise should be
training-time or prepared-catalog augmentation unless a deterministic
model-state effect requires rendering.

## Family A: `joint_full_v4`

Priority: highest new rendered family.

Purpose: broad low-discrepancy coverage of the full current 20-D science space,
with all science parameters allowed to vary simultaneously. This directly tests
whether corrections learned on structured V3 geometry generalize to arbitrary
joint perturbations.

Counts:

| split | science states |
| --- | ---: |
| train | 65,536 |
| validation | 8,192 |
| test | 8,192 |
| total | 81,920 |

Sampling:

- use independent deterministic scrambled Sobol sequences for train,
  validation, and test;
- train supports exact nested prefixes: 4,096, 8,192, 16,384, 32,768, 65,536;
- do not materialize independent smaller populations;
- no science-state overlap between splits;
- record Sobol dimension, scramble seed, sequence index, normalized
  coordinates, physical vector, Fisher vector, and Fisher radius.

Bounds:

- use the authoritative current V3 physical/Fisher parameter ranges from
  `parameter_space.json` plus resolved `experiment.sweeps`;
- record every bound source and transform;
- do not silently redefine ranges;
- because explicit lower/upper physical bounds are not currently a stable
  contract, Task 2 must materialize them as nominal plus/minus max absolute
  delta and flag any physical infeasibility for review.

## Family B: `radial_capture_v4`

Purpose: explicitly control initial Fisher-space distance from nominal and
support initializer/capture-region evaluation.

Counts:

| split | science states |
| --- | ---: |
| train | 16,384 |
| validation | 4,096 |
| test | 4,096 |
| total | 24,576 |

Sampling:

```text
delta_z = r * u_hat
```

`u_hat` is a full-dimensional direction and `r` is the requested Fisher-space
radius. Direction sequences should be deterministic, split-independent, and
recorded separately from radius selection.

Radius bins:

| requested radius bin |
| --- |
| 0-100 |
| 100-250 |
| 250-500 |
| 500-1000 |
| 1000-2000 |
| 2000-5000 |

Do not let high-dimensional volume effects determine the radial distribution.
The moderate-distance bins must be deliberately populated because S01/S05
results show some examples in the few-hundred to roughly 1000 Fisher-radius
regime can be made worse by learned correction.

Recommended split allocation for Task 2 QA: balanced or intentionally
near-balanced counts per radial bin within each split, with exact integer
remainders assigned deterministically.

Bound handling:

- independent component clipping is not allowed;
- compute a direction-dependent feasible radius from physical bounds and either
  deterministically accept only requested radii with `r <= r_feasible`, or
  reject/resample the direction/radius pair using a fixed seed and recorded
  attempt count;
- record requested radius, actual radius, feasible radius, radial bin, and
  bound-handling status;
- if actual radius differs from requested radius, preserve both values.

The rendered dataset does not encode model-dependent labels. Future analyses
will calculate downstream metrics.

## Historical Sparse Family

Logical family alias: `sparse_mixture_legacy_100k`.

This is a first-class legacy family with 100,000 completed sparse rendered
states, 1-3 active science dimensions, a fixed 10-state nuisance bank, and
complete plan/manifest metadata. Do not rename, modify, or relabel the
underlying dataset.

Split policy: all records retain historical `split = "test"` provenance.

Allowed future uses:

1. Evaluation-only corpus that preserves historical test identity.
2. Exploratory/diagnostic analyses explicitly labeled non-confirmatory.
3. Source of an authoritative nuisance-bank candidate.
4. Compatibility reference for sparse-state generation.

Do not use this corpus as production training data. If sparse training is
needed, generate a new independent V4 sparse family.

Optional future family: `sparse_1to3_v4`. Generate it only if one of these
criteria is met:

- clean train/validation/test sparse splits are required;
- exact full nuisance cross-product sparse replication is required;
- improved combinatorial balancing is needed;
- updated parameter bounds make the legacy artifact incompatible;
- legacy metadata/provenance constraints prevent the intended analysis.

## Family C: `boundary_stress_v4`

Status: provisional.

Purpose: evaluate behavior near physical parameter-domain boundaries and
selected difficult corners/edges.

Initial scale:

- evaluation/validation: approximately 4,096 science states;
- train: initially zero or TBD;
- test: TBD.

Candidate strategies:

- near-bound normalized coordinates;
- selected high-dimensional corners;
- high Fisher radius near feasible boundaries;
- physically motivated combinations.

Do not freeze a production sampler without evidence. This family must not block
`joint_full_v4` or `radial_capture_v4`.

## Split Design

Freeze V4 science-state splits at state-generation time.

For `joint_full_v4`, train/validation/test use independent scrambled Sobol
sequences. Validation/test are not slices of train. The training sequence alone
provides nested data-scaling prefixes.

Use the same split-independence principle for `radial_capture_v4` and any
future sparse V4 family. No science-state overlap is allowed between train,
validation, and test. Test remains untouched during tuning.

Historical dataset split provenance is separate from new V4 split design. The
legacy sparse 100k corpus remains historically `test`.

## Capture-Oriented Future Metrics

V4 geometry must support later estimates of:

```text
||r_after|| / ||r_before||
P(||r_after|| < ||r_before||)
P(||r_after|| < R_ADORA)
```

conditioned on initial Fisher distance. Do not encode an assumed `R_ADORA` in
V4. The ADORA capture region will be characterized later.
